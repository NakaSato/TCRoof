## Source mapping and cause

The crashed thread starts in Swift's `_assertionFailure`, followed by
`closure #1 in static CrashReporting.configure()` at historical
`CrashReporting.swift:15`, then the dispatch main queue. That closure was the
temporary, DEBUG-only, explicitly requested test crash: three seconds after launch
with `-crashlyticsTestCrash`, it called
`fatalError("Crashlytics setup verification")`.

The source is `TCRoof/Diagnostics/CrashReporting.swift`; its caller is
`TCRoof/App/TCRoofApp.swift`, immediately after `FirebaseApp.configure()`.
The issue's blamed `TCRoofApp.swift:12` entry-point frame is lower in the stack;
the test closure and fatal-error message identify the cause. Historical line
numbers do not describe the current source after removal of that closure.

The supplied full thread dump also shows Crashlytics handling/symbolicating reports
and Firestore worker threads waiting. Those frames do not establish a Firebase
SDK fault or the cause of the separate project-list lag.

## Minimal fix and verification

The test scheduling block and its `fatalError` were removed during setup, before
this investigation. Keep that removal: `configure()` now only initializes the
reporter, sets the device-family key, and records app startup. No exception
handler, null check, or change to normal crash collection is needed.

Verified for this investigation:

- The current source contains neither the test launch argument nor its fatal-error
  message, and `configure()` schedules no delayed closure.
- The current built `TCRoof.debug.dylib` contains neither test string.
- The final build log records `BUILD SUCCEEDED` and successful symbol-upload
  validation after removal of the test trigger.
- W is running the installed final app at the bundle path recorded by that
  installation, with the test trigger removed.

Both the test build and fixed build report version `1.0 (1)`, so that version alone
cannot distinguish them. A historical issue remaining OPEN does not establish
that the current binary still contains the trigger. Physical iPad verification
remains separate from this iPhone event.
