# DEBUG launch arguments

Every DEBUG launch argument the app reads, to open a screen in a given state on a simulator or device. Read this when you need a screenshot or a state to check; add a new flag here, beside its area.

There is no Simulator.app here, so the simulator can't be rotated; landscape checks rely on these flags. Screenshot with `xcrun simctl io <udid> screenshot`.

```
xcrun simctl launch <udid> com.tcroof.internal -screen pwa -surveyDemo YES -surveyDemoSection YES -surveyWideA1 YES -surveyPage <page>
```

## App

- `-screen <name>` skips sign-in and opens one app screen as the root of its own stack, with no way back to the home (`TCRoofApp.swift` `DebugScreen`; `pwa` is the survey module, under the main dock). On iOS 27 a screen pushed over the home at launch stays blank, so don't push it.
- `-growattDemo YES|test` (DEBUG, with `-surveyHomeTab maintenance`) adds Growatt plants to the `บำรุงรักษา` overview (`GrowattDemoFeed`; nothing is saved). `YES` is the web portal's example plants (`TCRoofCore/GrowattWebDemo`: `server.growatt.com/login/toViewExamlePlant` opens a guest session, then the portal's own undocumented `index/getPlantListTitle`, `panel/getPlantData` and `panel/getDevicesByPlantList`; the home dashboard's plants and the business dashboard's (`indexbC/getPlantListTitle`), every page of their devices (4 a page); real systems with hidden names, live power and today's energy; what Growatt doesn't give (expected energy, PR, PM, repairs, modules) is made up from the plant's size by `TCRoofCore/MaintenanceMock`, filling only gaps and the same for a plant every time; `GROWATT_LIVE=1 swift test --filter GrowattWebDemoLiveTests` calls it). `test` is the OpenAPI test server (`TCRoofCore/GrowattAPI`, `test.growatt.com` with the API guide's public token; its sample plants never report; `plant/list`, then `plant/data` 6 s apart, since closer calls get `10012`). `-growattToken <token>` reads the company's own plants from `openapi.growatt.com` (`GrowattAPI.live`; the test token gets `10011` there); keep the token out of the repo. The line under the rows names the source and has `ดึงใหม่`. Without a Mac, the PWA settings' `นักพัฒนา` › `สถานีตัวอย่าง Growatt` switch (DEBUG builds only, `GrowattDemoSwitch`) keeps `growattDemo` on in the device's defaults.
- `-pwaPlanView schedule|mp|due` (iPhone, with `-screen pwa -surveyHomeTab plan`) picks the view of the `แผนงาน` page (`PWAPlanPhoneView`, `docs/ui/pwa-plan-iphone`). `-pwaPlanDemo YES` shows the board's example instead of the jobs (nothing is saved), dated from today, with the calendar's bars from the board's `monthTypesByDay`; add `-pwaPlanToday 2026-10-12` to fix "today" on the board's Monday. `-pwaPlanCalendar week|month` picks the calendar's view, `-pwaPlanDay 2026-10-15` selects a day and scrolls the day list to it, `-pwaPlanFilter open|ins-A|empty` opens `กรองตารางงาน`, or sets `ติดตั้ง` + contractor A, or a filter with no match; `-pwaPlanDueFilter open|doc` opens the `กำหนดส่ง` filter menu or picks `ยื่นเอกสาร`; `-pwaPlanSearch YES` opens the header's search. On iPad (`-surveyHomeTab plan`, best with `-screen home -homeTab pwa -homeBoard YES` for the landscape layout) the same flags work except `-pwaPlanView`, `-pwaPlanFilter` and `-pwaPlanDueFilter` (the iPad page shows all three views and no filters), and `-pwaPlanScrollEnd YES` opens the right column at its end.
